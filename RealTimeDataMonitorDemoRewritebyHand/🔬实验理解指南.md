## 🧪 实验2：理解"过滤机制"

### 目标：看看服务器是怎么过滤数据的

### 动手操作：

在 `app/grpc_server.py` 的 `SubscribeTelemetry` 方法中添加日志：

```python
def SubscribeTelemetry(self, request, context):
    filter_expr = request.filter  # e.g., "type=SYSTEM"
    
    # 👀 添加这行：看看客户端要订阅什么
    print(f"📡 客户端订阅请求: {filter_expr}")
    print(f"📦 当前存储箱有 {len(self.telemetry_datasource)} 条数据")

    for telemetry_data in self.telemetry_datasource.values():
        # 👀 添加这行：看看每条数据的检查过程
        print(f"🔍 检查数据: ID={telemetry_data.id}, 类型={telemetry_data.type}")
        
        # 简单示例：按类型匹配
        if filter_expr and filter_expr.startswith("type="):
            expected_type = filter_expr.split("=", 1)[1]
            # 👀 添加这行：看看匹配逻辑
            print(f"   期望类型: {expected_type}, 实际类型: {str(telemetry_data.type)}")
            
            if str(telemetry_data.type) != expected_type:
                print(f"   ❌ 不匹配，跳过")
                continue
            else:
                print(f"   ✅ 匹配，推送给客户端")

        yield telemetry_pb2.TelemetryServiceSubscribeTelemetryResponse(
            telemetry = telemetry_data
        )
```

```python
def SubscribeTelemetry(self, filter: str):
    """订阅遥测数据 - 服务器流式推送（基础版本）"""
    print(f"📡 开始订阅遥测数据，过滤条件: {filter}")

    request = telemetry_pb2.TelemetryServiceSubscribeTelemetryRequest(
        filter=filter
    )
    
    try:
        # 调用服务器流方法，返回一个响应流迭代器
        response_stream = self.stub.SubscribeTelemetry(request)
        
        print("✅ 订阅成功，等待服务器推送数据...")
        
        # 👀 添加计数器
        count = 0
        
        # 遍历服务器推送的数据流
        for response in response_stream:
            count += 1
            print(f"🔄 第{count}次推送 - 收到遥测数据: ID={response.telemetry.id}, 类型={response.telemetry.type}")
            # 这里可以添加数据处理逻辑
            
        # 👀 添加总结
        print(f"📊 总共收到 {count} 条推送数据")
            
    except grpc.RpcError as e:
        print(f"❌ 订阅请求失败: {e}")
    except Exception as e:
        print(f"❌ 订阅过程中发生错误: {e}")
```

**理解：** 客户端通过for循环"等待"服务器推送，每个yield都会触发一次循环

## 💡 实验总结

通过这些实验，您应该理解了：

1. **数据存储**：服务器用字典存储数据，key是ID
2. **过滤机制**：服务器遍历所有数据，只推送匹配的
3. **流式通信**：客户端用for循环接收服务器的多次推送
4. **错误处理**：没有数据、网络问题等都会有相应的表现
