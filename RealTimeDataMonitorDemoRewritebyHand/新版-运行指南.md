# gRPC 服务器和客户端通讯测试指南

## 📋 项目概述

这是一个基于 gRPC 和 Protocol Buffers 的实时数据监控系统，支持遥测数据的发送、获取、流式传输和订阅功能。

## 🚀 快速开始

### 1. 环境准备

确保已安装以下依赖：
```bash
pip install grpcio grpcio-tools protobuf
```

### 2. 一键测试通讯

运行集成测试脚本（推荐）：
```bash
python test_communication.py
```

这个脚本会：
- ✅ 自动启动 gRPC 服务器
- ✅ 测试客户端与服务器的基本通讯
- ✅ 测试错误处理机制
- ✅ 自动清理资源

### 3. 手动分离测试

如果需要分别启动服务器和客户端：

#### 启动服务器
```bash
# 方法1：使用测试服务器脚本
python -m test.server

# 方法2：直接运行
python test/server.py
```

#### 运行客户端
```bash
# 使用客户端测试代码
python app/grpc_client.py
```

## 📡 支持的 gRPC 方法

### 1. SendTelemetry (单向调用)
- **功能**: 发送遥测数据到服务器
- **类型**: Unary RPC
- **请求**: `TelemetryServiceSendTelemetryRequest`
- **响应**: `TelemetryServiceSendTelemetryResponse`

### 2. GetTelemetry (单向调用)
- **功能**: 根据 ID 获取遥测数据
- **类型**: Unary RPC
- **请求**: `TelemetryServiceGetTelemetryRequest`
- **响应**: `TelemetryServiceGetTelemetryResponse`

### 3. StreamTelemetry (双向流)
- **功能**: 双向流式传输遥测数据
- **类型**: Bidirectional Streaming RPC
- **请求**: `TelemetryServiceStreamTelemetryRequest` (流)
- **响应**: `TelemetryServiceStreamTelemetryResponse` (流)

### 4. SubscribeTelemetry (服务器流)
- **功能**: 订阅遥测数据推送
- **类型**: Server Streaming RPC
- **请求**: `TelemetryServiceSubscribeTelemetryRequest`
- **响应**: `TelemetryServiceSubscribeTelemetryResponse` (流)

## 🔍 故障排除

### 常见问题

1. **导入错误**
   ```
   ImportError: cannot import name 'telemetry_pb2' from 'telemetry.v1'
   ```
   - **解决方案**: 确保已添加 `__init__.py` 文件到所有包目录

2. **端口占用**
   ```
   grpc._channel._InactiveRpcError: <_InactiveRpcError of RPC that terminated with: status = StatusCode.UNAVAILABLE
   ```
   - **解决方案**: 检查端口 50051 是否被占用，或更改端口号

3. **protobuf 版本不兼容**
   ```
   AttributeError: module 'telemetry_pb2' has no attribute 'TelemetryType'
   ```
   - **解决方案**: 检查 protobuf 定义，使用正确的枚举名称（如 `DataType`）

## 📝 开发说明

### 数据存储
- 当前使用内存字典存储遥测数据
- 生产环境建议使用 Redis 或其他持久化存储

### 并发处理
- 服务器使用 ThreadPoolExecutor (10 个工作线程)
- 可根据负载调整线程池大小

### 错误处理
- 实现了标准的 gRPC 错误码
- 支持 NOT_FOUND、UNIMPLEMENTED 等状态码
